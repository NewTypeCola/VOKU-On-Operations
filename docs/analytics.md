# VOKU On 이용 분석 운영 기준

기준일: 2026-10-14. 지표 정의: `voku-usage-v1`. 목적은 관측된 아카이브 이용과 커뮤니티 참여를 재현 가능한 근거로 설명하는 것이다. 방문자를 실제 사람 수로 표현하거나 과거에 없던 기록을 추정해 채우지 않는다.

## 실제 구성

```text
voku-video (React / 모바일)
  analytics facade → 별도 runtime + Web Vitals
      ↓ 같은 출처 POST /api/usage (최대 32 KiB)
Cloudflare Pages Function
  Origin·크기·봇 신호 검증, IP 일별 HMAC 요청 제한 키
      ↓ 공개 API 키 + 수집 전용 비밀값 (+ 로그인 JWT)
공유 Supabase
  usage_ingest → voku_metrics (일반 회원 직접 접근 불가)
  catalog / events / sessions / visitors / daily / snapshots / health
      ↓ ops_usage_* → 기존 voku_ops.require_operator(AAL2)
voku-operates (React / 데스크톱)
  기간·대상 조회 / 아카이브·이동·기능·오류 / CSV·검증 JSON
```

`voku_ops`와 `voku_private.members`의 권한은 계속 분리된다. 기존 게시판 관리자의 권한이나 로그인 방식은 바꾸지 않는다. 최고운영자·운영자·조회 담당자는 모두 통계를 조회하고 내보낼 수 있으며, 일반 회원과 게시판 운영진에게는 통계 RPC 권한이 없다. 원시 이벤트를 내려주는 API는 없다. 운영 화면에도 브라우저별 이동 이력이나 회원별 감시 화면을 만들지 않았다.

## 지표와 한계

| 항목 | 정의 |
| --- | --- |
| 관측 브라우저 | 서버에서 해시한 임의 브라우저 식별값의 기간 내 중복 제거 수. 사람 수가 아님 |
| 방문 세션 | 탭별 식별값. 30분 비활동 또는 24시간 경과 시 새로 생성. 여러 탭은 여러 세션 |
| 재방문 브라우저 | 최초 관측에서 30분 이상 지난 후 새 세션이 생성된 브라우저. 동일 식별값의 재방문만 관측 |
| 화면 보기 | 라우트가 바뀐 경우. 검색어 변경 자체는 새 화면으로 부풀리지 않음. 게시글은 실제 내용을 읽을 수 있게 된 후 기록 |
| 열람 시작 | 회차 열기. 이미지 로딩 실패·즉시 이탈도 시작에는 포함 |
| 활성 열람 시간 | 이미지가 로드되어 화면의 의미 있는 영역에 보이고, 탭이 보이며 최근 60초 이내 조작이 있을 때. 중단된 타이머 간격은 최대 2초만 인정 |
| 30초 이상 열람 | 선택 기간 내 동일 세션·회차의 활성 이미지 열람 시간이 합계 30초 이상 |
| 읽은 쪽 | 쪽 이미지가 누적 2초 이상 보인 경우. 세션·회차·쪽별 중복 제거 |
| 90% 쪽 확인 | 30초 기준 충족 + 카탈로그 전체 쪽수의 90% 이상 확인. 내용 이해/실제 완독의 증거는 아님 |
| 열람 후 작성 | 같은 세션에서 30초 기준을 먼저 충족하고 이후 글 또는 댓글 작성 성공. 실제 DB 작성자·최근 작성 기록 대조, 레코드별 중복 제거 |
| 글쓰기 진입 | 위 열람 기준 이후 큐시트의 글쓰기 버튼으로 진입. 댓글 작성 경로와 별도 지표 |
| 이탈 지점 | 세션의 마지막 관측 화면. 열린 세션이나 전송 실패는 실제 종료와 다를 수 있음 |
| Web Vitals | 공식 라이브러리 LCP·INP·TTFB(ms), CLS×1,000. RPC 지연은 1초 이상 요청만 기록 |

브라우저 데이터 삭제, 여러 기기, 180일 식별값 교체는 중복을 만든다. 자바스크립트 미실행·차단·통신 실패는 누락을 만든다. 봇 신호가 없는 자동화를 모두 판별할 수는 없다. 읽는 동안 조작이 없는 사용자는 시간을 보수적으로 집계한다. 전환은 시간 순서가 있는 연관 관측이며 인과관계를 입증하지 않는다. 검색어, 본문, 전체 URL, DOM 선택자, 오류 메시지·스택은 수집하지 않는다.

카탈로그 기준은 `voku-video/public/data/catalog.json`: 5,330회차 / 66,010쪽. Hugging Face `NewTypeCola/VOKU-Archive` revision `946efb631be114cbbc410fa4bceeed4df0559010`, catalog SHA-256 `74030ffc4db9bce13c41c2d109c969b605bb054a3624fdcaa450a97065bd6521`. 카탈로그가 바뀌면 검증 후 별도 데이터 마이그레이션으로 갱신한다.

## 실사용과 제외 활동

기본 `real` 조회는 운영 환경의 관측 중 아래를 제외한다. `all` 조회는 검증·진단에 사용하며 외부 실사용 실적과 혼합하지 않는다.

- 로그인 JWT의 실제 회원 역할이 admin/moderator이거나 운영자 테이블에 있는 계정: staff. 인식된 브라우저의 보관 중 세션도 제외하고 로그아웃 뒤에도 해당 식별값이 유지되는 동안 제외한다. 로그인하지 않은 별도 브라우저의 관리자임을 알아내지는 못한다.
- `?usage_test=1`로 시작하거나 개인정보 페이지에서 테스트 표시: test. 설정은 해당 브라우저에 남으며 `?usage_test=0` 또는 설정 해제로 다음 세션부터 해제한다. CI·시연·사용성 점검에서 먼저 설정한다.
- Cloudflare 미리보기 도메인: test. `voku.pages.dev`만 운영 환경으로 분류한다. 운영 도메인이 바뀌면 collector의 정확한 호스트 허용 목록도 갱신한다.
- `navigator.webdriver`, 알려진 자동화 User-Agent, 제공되는 경우 Cloudflare 봇 신호: bot. 유료 봇 관리 기능을 설치하거나 결제하지 않았다.
- 게시글 `sample_batch`, 댓글 `is_sample`, 로컬 예시 화면: sample. 클라이언트 표시를 믿는 것에 그치지 않고 실제 DB 플래그로 확인한다. 일반 회원이 관리자 작성 글을 읽는 것은 실사용이며, 관리자 자신의 활동과 구분한다.

서로 겹칠 때 세션 분류는 bot → test → staff 순이고, sample은 나머지 real 이벤트 중 별도로 표시한다. 기존 누적 조회수는 이 기준으로 정제된 수치가 아니므로 별도 참고 영역에 둔다. 기존 DB의 작성 시각·예시·역할·현재 아카이브 저장 수를 재사용한다. 과거 회차 열람·재방문·날짜별 게시글 조회는 복원하지 않는다.

## 전송, 보안, 수집 상태

- 렌더링·회원 기능을 기다리게 하지 않는 별도 모듈. 15초 또는 20개 이벤트에서 전송. 활성 시간은 1초 간격의 가벼운 검사로 누적한다.
- 브라우저 메모리 큐 최대 300개, 한 번에 20개, 실패 시 최대 두 번 재시도. 이벤트 UUID로 중복 제거. 영구 오프라인 큐·재생·입력 캡처를 만들지 않았다.
- 숨김·종료 시 `keepalive` 전송. 전송 유실을 완전히 제거할 수 없으며, 전달 가능한 유실 수만 후속 요청에 알린다.
- 원문 IP·UA를 저장하지 않는다. IP의 일별 HMAC은 요청 제한 목적으로만 최대 2일 보관한다. 동일 IP 범주의 요청은 분당 120배치 제한한다. 공유 네트워크의 대규모 동시 이용은 이 제한에 영향을 받을 수 있다.
- 수집 키는 Cloudflare `USAGE_INGEST_KEY`(secret_text)와 DB의 SHA-256 값으로 분리한다. 권한은 수집/현재 브라우저 상세 기록 삭제에만 쓰이며 service_role 키는 사용하지 않는다.
- `Origin`, 요청 크기, 버전, 이벤트·화면·세부 분류 허용 목록, 시간 범위, 카탈로그와 쪽 범위를 서버에서 검증한다. 공개 API 키만으로 직접 수집 RPC를 호출할 수 없다.
- 로그 조회는 기존 이메일 확인·활성 운영자·실제 세션·AAL2 검사를 재사용한다. 공개 함수는 invoker 래퍼, 내부 함수는 빈 search_path와 명시적 권한 검사를 사용한다.
- 수집 상태에서 마지막 수신, 허용/거부/중복/전송 유실, 저장 용량, 보관 작업 실행 시각을 확인한다. 용량·실행 시간의 추이를 보고 요금제 한도에 닿기 전에 운영자가 보관 정책/집계를 검토한다. 유료 요금제로 자동 변경하지 않는다.

## 보관과 개인정보 선택

상세 이벤트·세션은 90일 기준으로 일 단위 삭제한다(날짜 경계와 정리 주기로 약 하루의 차이가 생길 수 있음). 재방문용 서버 식별값은 마지막 수신 후 180일, 브라우저 식별값은 생성 후 180일. 식별값 없는 일별 집계와 보고서는 5년이다. `voku-usage-retention` pg_cron 작업은 매일 UTC 19:20 / 한국 시간 04:20에 실행한다. 이 작업의 실행 이력만 30일 보관한다. 다른 서비스의 로그는 정리하지 않는다.

`/privacy/`에서 분석 허용을 끄거나, 이 브라우저의 보관 중 상세 기록을 삭제할 수 있다. DNT/GPC도 존중한다. 기능 제공·보안 로그는 별도다. 삭제 요청에 실패하면 임의 식별값을 남겨 재시도할 수 있도록 한다. 이미 식별값 없이 만든 일별 집계와 내보낸 보고서는 남는다. 공개 개인정보처리방침에 항목·목적·수집 경로·보관·거부·삭제를 반영했다. 이것은 법률 검토나 포괄적 준법 인증을 의미하지 않는다.

## 보고서 작성 절차

1. 상세 이용 분석에서 기간(KST)과 `실사용 관측만`을 선택한다. 최근 90일의 상세 지표를 비교할 수 있다.
2. 수집 시작일·오류·거부·유실·제외 건수를 함께 확인한다. 기간에 수집 시작 전 날짜가 포함되면 미관측 기간을 명시한다.
3. 아카이브의 30초 열람, 읽은 쪽, 후속 참여를 이용 가치 지표로 사용한다. 빈 데이터는 0 또는 미관측으로 보고하며 가상 수치로 채우지 않는다.
4. CSV는 분석용, 증빙 JSON은 스냅샷 보존·검증용이다. 매 내보내기가 별도 스냅샷과 운영 감사 기록을 만든다. CSV와 JSON 버튼을 각각 누르면 생성 시각이 다를 수 있다.
5. 장기 일별 집계는 한 번에 최대 367일 조회한다. 일별 브라우저·세션·회차 수의 합을 기간 순이용자 수로 발표하지 않는다. 필요하면 여러 기간의 집계를 각각 내려받는다.
6. 외부 자료에 지표 버전, 기간, 수집 시작일, 제외 기준, 표본·한계와 보고서 ID/체크섬을 함께 적는다. JSON에는 브라우저·세션·회원 ID가 없다.

검증은 내보낸 JSON의 `canonicalPayload` 문자열을 UTF-8 그대로 SHA-256 계산해 `sha256`과 비교한다. 이는 파일 내용의 변경 여부를 확인하며 사용자 수의 독립 감사나 데이터 진실성을 보증하지 않는다. 필요하면 데이터베이스 백업 및 스냅샷을 별도로 대조한다. 익명 브라우저 행동은 서버에 도달하더라도 인간의 활동임을 암호학적으로 증명하지 못한다.

## 배포·장애 대응

두 저장소가 공유 DB를 쓰므로 마이그레이션을 무차별 `db push` 하지 않는다. 각 SQL의 선행 조건과 원격 적용 목록을 확인해 순서대로 적용한다. community SQL은 voku-video가 소유하고, ops/metrics SQL은 이 저장소가 소유한다. `tests/fixtures/community`는 통합 검증용 사본이다.

새 환경: 기존 community → operations dashboard → usage analytics → catalog → retention 순. 수집 전용 임의 32바이트 키의 hex 문자열을 Cloudflare secret에 넣고 그 문자열의 SHA-256을 `voku_metrics.config.ingest_hash`에 설정한다. 키가 없는 환경은 수집 실패로 닫힌다. 브라우저 빌드에 키를 넣지 않는다. 기존 Cloudflare Git 배포를 사용하며 마이그레이션을 먼저 적용한다.

웹앱의 `public/_routes.json`에는 `/api/usage`, `/api/usage/*`를 포함한다. 이 경로가 빠지면 정적 호스팅에서 POST가 405로 끝나므로 배포 후 `scripts/verify-analytics-live.mjs` 검사도 실행한다. 기존 `/share/*`, `/p/*` 경로는 유지한다. [Cloudflare의 Git 배포 API](https://developers.cloudflare.com/api/resources/pages/subresources/projects/subresources/deployments/methods/create/)와 기존 Git 연결을 사용한다.

수집 장애가 서비스 기능 장애로 전파되지 않도록 설계했다. 긴급 중지 시 Cloudflare 수집 키를 제거하면 수집이 닫힌다. 원시 테이블을 급히 삭제하거나 공유 Auth를 변경하지 않는다. 통계 정확성 수정에는 새 정의 버전/마이그레이션과 변경 사유를 남긴다.
